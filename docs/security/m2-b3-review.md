# M2 increment B3 security review (AI gateway, mock client, rolling summary, Quick recap, budget ledger)

Reviewer: security-engineer (independent of the implementer). Date: 2026-10-27. Scope: the UNCOMMITTED working tree on top of `7aa359d`: `src/api/src/Modules/Ai/Tether.Ai` (gateway, mock client, summary engine and scheduler, catch-up service and runner, ledger, budget math, validators, sanitizer, prompts, endpoints, migration A001), `Transcript/Application/AiPorts.cs` and its wiring (Transcript module, hub Join, relay observers, Host `Program.cs`), `tests/Tether.AiTests`, and the frontend realtime wiring (`src/web/src/lib/lecture/realtime`, `components/lecture/realRuntime.ts`). Reference: `docs/API_CONTRACTS.md`, `docs/ai/live-lecture-ai-design.md`, `docs/security/m2-b2-review.md` (format).

**No gate is cleared by this review.** G1 (recording/consent) stays BLOCKED, G2 (vendor, cost, limits) UNVERIFIED, G3/G4 NOT_RUN, G5 BLOCKED. The only AI provider in this increment is a deterministic mock. Nothing here says anything about how a real model behaves.

## Method
- **READ** = code reading only. **RAN** = executed by me.
- RAN: a scratch Node script that replays the sanitizer's four regexes in the same order (JS and .NET regex agree on these constructs). It lives in the session scratchpad, not in the repo.
- NOT RUN: the .NET build, `Tether.AiTests`, the integration suite, any HTTP probe against a running API. I did not start the stack. Every "READ" finding is from code, not from a reproduced request.
- No file under `src/` or `tests/` was changed.

## Verdict
**No Critical or High findings.** Three Medium, five Low, five Info. None blocks local mock-only development. B3-01, B3-02 and B3-03 must be fixed before a real Claude adapter exists (the mock cannot hit them in a way that costs money or reaches a user). B3-06 and B3-12 are decisions for the Product Owner before any real transcript text goes to a vendor.

### Verified sound
- **Ownership on the three routes (C-09), READ.** `GET /summary` and `GET /catch-ups/{id}` call `ISessionDirectory.FindAsync(userId, id)` first and return the same `Problems.NotFound` for "not yours" and "does not exist" (`AiEndpoints.cs:31,74`). `POST /quick-recap` does the same inside `CatchUpService.StartAsync` (`CatchUpService.cs:63-64`). A malformed `catchUpId` gives 404, not 400 (`AiEndpoints.cs:75`). Every AI table carries `user_id` and an EF global query filter on the current user (`AiDbContext.cs:49,77,104`), so a second layer holds if the directory check is ever dropped. `CatchUpService.GetAsync` also filters on `SessionId`, so a catch-up id from another of the user's own sessions does not resolve under this session.
- **Authentication, READ.** The Identity module sets a `FallbackPolicy` of authenticated user (`IdentityModule.cs:88`), so the AI group is not anonymous even though `AiEndpoints.Map` has no `RequireAuthorization`. The handlers also return 401/404 when `ICurrentUser.UserId` is null. State-changing POST is behind `OriginCheckMiddleware` (`Program.cs:157`), JSON content type is required (`AiEndpoints.cs:38`), the body is capped at 64 KB globally (`Program.cs:23`), and the closed body shape `{windowMinutes: 2|5|10}` is enforced by hand.
- **Cross-schema integrity, READ.** `summary_revisions` and `catch_ups` have composite FKs `(session_id, user_id)` to `lectures.lecture_sessions` with `ON DELETE CASCADE` (migration lines 144-149). A row cannot name another user than its session, and deletion removes derived data (C-21). The ledger has deliberately no session FK, so deleting a lecture does not hand back the daily budget. It cascades from the user.
- **Background paths stay user-scoped, READ.** `CreateUserScope(userId)` is used by both the summary engine and the catch-up runner. `TranscriptSegmentReader` refuses any `userId` other than the scope's (`AiPorts.cs:16,20,29,39,51`) on top of the EF filter.
- **The real provider is impossible without explicit config (and, today, with it), READ.** `AiProviderGuard.Validate` throws at startup for any `Ai:Provider` other than `mock` (`AiOptions.cs:84-92`): first listing a missing key and missing explicit budgets, then refusing even when both are present because no adapter exists. `IAiClient` is registered only as `MockAiClient` (`AiModule.cs:35-36`). Mock fault injection and mock latency are refused outside Development/Test (`AiOptions.cs:93-96`). The API key is never stored in `AiOptions`. Default budgets are positive, so zero or negative caps fail startup. No OAuth token, cookie or other user's id is in `AiRequest` (it carries only the owner's `UserId` for the ledger).
- **No tools, no free-form egress, READ.** `AiRequest` has no tool field. The system prompt always ends with `DataPreamble` (appended in `PromptRenderer.Render`, so no workflow can omit it). Transcript lines are inside a tag with a per-request random id, `<` and `>` are replaced by look-alike characters, control characters are dropped, lines are capped at 2000 characters, and e-mail, key-like, bearer, JWT, long-token and phone patterns are redacted before the text leaves (`PromptRenderer.cs:52-83`). `RepairHint` is a vocabulary code, never model or transcript text.
- **Citations are server-resolved, READ.** Timecodes come from the stored segment (`CitationRef(id, line.StartMs)`), never from the model. Unknown ids are dropped. A "lecture" claim with no valid id is relabelled `uncertain`. A summary topic with no valid citation is dropped, and zero grounded topics rejects the whole delta (`Validators.cs:88-113,217-220`). Closed object shapes with duplicate-name rejection (`JsonShape.Exactly`) and `MaxDepth = 8` apply to model JSON.
- **Logs (C-23/C-24), READ.** Every `Log*` call in the module logs a type name, a fixed vocabulary code, a workflow/kind enum, or a session id. None logs transcript, prompt, completion or exception text (grep of `Log(Information|Warning|Error...)` across `Tether.Ai`). `ILogger` is never handed an exception object. The ledger holds counts, model name, outcome and latency only. The host's exception handler logs type and trace id only (`Program.cs:141-148`).
- **Error leakage, READ.** Failure reasons on the wire come from `AiFailure.ToWireReason` (fixed vocabulary). Validation errors name the field, not the value. The 500 path is generic.
- **Idempotency (quick-recap), READ.** Key is 1-64 chars of `[A-Za-z0-9_-]`; the unique index is `(user_id, session_id, idempotency_key)`; a replay with the same window returns the stored row with `Idempotency-Replayed: true`, a different window gives a validation error, and a concurrent insert race is resolved through the unique violation (`CatchUpService.cs:67-71,101-106`).
- **Summary append is optimistic and append-only, READ.** `AppendAsync` checks `max(revision) == expectedBase`, and the composite primary key backs it up (unique violation becomes `Stale`). A late job cannot recreate rows for a deleted session (FK violation becomes `SessionGone`).
- **Frontend wiring, READ.** `HubTransport` is WebSockets-only, same-origin, cookie auth, `LogLevel.None`, automatic reconnect off. `eventGuard` structurally validates every inbound event, ignores extra fields, and `hubErrorCode` maps to a fixed code set so server text never reaches the UI. Server text is rendered through `PlainText`; a grep of non-test `src/web/src` finds no `dangerouslySetInnerHTML`, `innerHTML`, or markdown library (the lecture README says a test enforces this). The web app has no call to `quick-recap` or `catch-ups` yet, so the REST half of the AI surface has no client in this increment.
