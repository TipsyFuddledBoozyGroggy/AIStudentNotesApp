# M2 increment B2 security review (transcript module, lecture hub, audio relay, replay STT)

Reviewer: security-engineer (independent of the implementer). Date: 2026-10-28. Scope: commit `be79f1c` "Add M2 increment B2" against `docs/API_CONTRACTS.md` (frozen v1 and section 15), `docs/architecture/m2-b2-realtime.md`, `docs/security/m2-contract-review.md` (C-01..C-32) and `docs/security/m2-b1-review.md` (B1-12 deferrals).

**No gate is cleared by this review.** G1 (recording/consent) stays BLOCKED, G2 UNVERIFIED, G3/G4 NOT_RUN, G5 BLOCKED. Consent text `draft-1` is DRAFT. All audio used here was synthetic zero-PCM against `ReplaySttProvider`; no microphone, no real lecture and no vendor was involved.

## Method
- **READ** = code reading only. **RAN** = executed by me.
- RAN: full suite in Docker (`docker compose ... run --rm dotnet dotnet test src/api/Tether.slnx`): ContractTests 105/105, ArchitectureTests 15/15, IntegrationTests 284/284 pass.
- RAN: black-box probes against the running dev API (`http://localhost:5080`, users alice@dev.local and bob@dev.local) with a hand-written WebSocket/SignalR client (Node, scratchpad only, not committed). Read-only `psql` queries against the dev database to confirm cascades and constraints. No file under `src/` or `tests/` was changed; no container was restarted. Side effects: probe courses and sessions in alice's and bob's dev data (all stopped or purged).

## Verdict
**No Critical or High findings.** The core B2 controls hold under probing. Two Medium findings: one blocks the frontend connecting (B2-01), the other blocks non-dev use (B2-02). Eleven Low or Info items follow. Several matter only once a real STT vendor receives audio. They are listed so they get fixed before that, not discovered after.

### Verified sound
- Origin (C-03/C-07), RAN: `/ingest/...` and `/hubs/lecture` (GET upgrade and POST negotiate) return 403 `csrf_failed` before auth or upgrade for a missing Origin, `null`, another port, `https`, a suffix domain (`localhost:3000.evil.com`), uppercase, trailing slash, userinfo and a duplicated header. Also for `/HUBS/Lecture` and `/%68ubs/lecture`. The good Origin with no cookie gets 401. Long polling and SSE return 404, negotiate offers WebSockets only.
- Ticket (C-01/C-02), RAN: a replayed consumed ticket gets 4401. A concurrent double-consume gives exactly one winner. Bob using Alice's ticket on her session gets 4401 and does not burn it. A ticket minted before pause gets 4401 after pause, and issuing a ticket on a Paused session gets 409. A garbage ticket gets 4401. READ: the cookie user, login-session id, session and expiry are all checked (`AudioTicketService.cs:131-136`). A non-Active session closes 4401, which is the documented deviation (section 15 item 8). I accept it as C-01-consistent.
- Pre-auth limits (C-04/C-25), RAN: binary before hello closes 1008. A 2 KB hello, a 100 KB text message, an unterminated 20 KB fragmented message and an oversize binary frame each close 1009. Upgrades are capped at 10/min per user (the 11th gets 429). Sending 25 s of audio in a burst got 22 acks (the 5 s x 1.1 budget), one `rate_limited`, then a 1008 close.
- Cutoff (C-14), RAN: REST pause closed the socket 4409 in 44 ms. After pause the transcript held only `session.state` events. READ: the seq allocation re-checks Active inside the counter-row lock (`SessionPortsService.cs:45-62`), so a late write rolls back without leaving a seq gap.
- Isolation (C-09), RAN: Bob reading Alice's `/transcript` and Bob reading a missing id return byte-identical 404s. A foreign Join and a missing Join give identical `not_found`. `limit=501` and `afterSeq=-1` give 400. A huge `lastSeq` gives an empty replay, an overflowing or numeric `lastSeq` gives `validation_failed`, and an extra field gives `validation_failed`. A 5 KB hub message closes the connection. A 4th hub connection for the user is aborted. Group names are built server-side from user id and session id (`LectureHub.cs:30`).
- Deletion (C-21), RAN: `DELETE /courses/{id}?purge=true` during streaming closed the socket 4409 after 1.6 s and the hub connection after 3.2 s. `transcript_events` and `audio_progress` rows for the session were 0 afterwards. `pg_constraint` shows both new FKs as `ON DELETE CASCADE` on `(session_id, user_id)`.
- Logs (C-23/C-24), READ plus the canary test (RAN within the suite): exceptions are logged by type only (`RelayConnection.cs:116,305,317,340`, `LectureHub.cs:159`). The canary runs at Trace with a failing-row path and checks text, audio bytes (raw, base64 and hex), tickets and cookies. Hub and socket error text comes from a fixed vocabulary.
- Replay STT, READ: `IsDemo` is hard-coded `true` and `Name` is `replay-demo` (`ReplaySttProvider.cs`). Startup throws for any `Speech:Provider` other than `replay` (`TranscriptModule.cs:37-39`). RAN: sessions report `demoSource: true`.

| B2-01 | **Medium** | RAN | **A student's Pause can be refused.** The transition cap exempts only Stop and system transitions (`SessionService.cs:194`, `319-327`), so a user **Pause** returns 429 once 12 transitions happen in a minute or 200 in the session. Reproduced: after 6 pause/resume pairs, the 13th call (a Pause while Active) got 429 `rate_limited` and the session stayed **Active**. Pause is a privacy control (invariant 2, C-14). | B2-02 | **Medium** | RAN | **Hub Join is unbounded across session ids, and its limiter leaks memory.** `JoinLimiter` is keyed by `(user, session)` and runs before the lookup (`LectureHub.cs:60`, `172-187`). ## Multi-instance (single instance only; what breaks with two)
`HubConnections`, hub groups, `PartialStore`, `RelayRegistry`, `SessionActivityTracker`, `JoinLimiter`, `FailedHelloLimiter` and the ASP.NET rate limiters are all in-process. With two instances:
- Events from the instance that holds the audio socket do not reach hub clients on the other instance.
- A pause or delete handled on instance B does not cut the socket on A until A's 5 s check.
- Instance B's lifecycle job sees no activity for a session that is streaming on A and **auto-pauses it every 5 min**.
- Every limit is multiplied by the instance count.
- `HubReaper` cannot abort connections that live on another instance.

Before scale-out: a SignalR backplane, shared activity, limiter and relay state (or sticky sessions plus leader election for the job), and push-based revocation. Hosted jobs run on every instance; transitions stay idempotent (xmin plus the `s.State == target` short-circuit), so no duplicate events were found by reading, but this was not run.
