## Recommendation on freezing `syllabus.v1` for mock-only implementation

**Conditional YES.** The revision is a real improvement and no Critical or High issue remains in the contract text. Do not freeze it as it stands, because the freeze rule is additive-only and six items below change the wire shape or normative text in ways that would be breaking (or at least awkward) after the freeze. Make these edits first, then freeze with a delta check from me (about an hour of work):

1. R2-01: replace `$` with an end-of-input form in every pattern (trailing LF currently validates; verified).
2. R2-04: decide now whether `snippet.text` is purged with the canonical text. Making it nullable after the freeze is a breaking response change.
3. R2-11: define what `syncState: sync_failed` and `syncedRevision` mean for an item that has never synced (the schema makes that state unrepresentable).
4. R2-05: state one canonical wire form for ids (exact case and format) and de-duplicate after decoding.
5. R2-06: add the schema rule `hiddenContentRemoved > 0` implies `hiddenContentDropped: true`, and state when stripped tag/bidi characters raise `injectionSuspect`.
6. R2-10: put the idempotency lookup into the section 2.1 evaluation order and fix the create-replay contradiction.

Everything else (R2-02, 03, 07-09, 12-21, D-nn) can land as text, tests or tightened server rules during implementation without changing the freeze. The data design `docs/data/schema-syllabus-p2.md` must be reconciled (D-01..D-14) **before migration S001 is written**, not before the contract freeze. This freeze is for the mock provider and synthetic data only. It says nothing about real-document use.

### ReDoS and Unicode regex check (ran)

The title and notes patterns are linear. Probe timings on adversarial inputs: title with 50,000 characters ending in LF 1.1 ms; 50,000 combining marks 0.3 ms; 50,000 spaces 1.2 ms; notes at 500 characters with 9 newlines and with 499 combining marks below 0.1 ms. The lookahead `(?!(?:[^\n]*\n){10})` cannot backtrack exponentially because `\n` delimits each repeat. **No ReDoS found.** Still apply a server match timeout. Bypass results are in R2-01 to R2-03.
