## Part 3: Assessments requested

### (a) Transient-bytes design: tmpfs shared with the sandboxed parser, no DB bytes, orchestrator/parser split, in-flight cap

**Acceptable in principle, and strictly better than the withdrawn UNLOGGED table**, because the R2-13 problems (heap and TOAST residue, `pg_dump` and snapshot inclusion, parameter logging, DB memory pressure, WAL) disappear when bytes never reach Postgres, and unlinking a tmpfs file frees the memory at once. I verified the text is consistent across contract 1 (row 5), 5.1 items 8-9, 5.2, section 10, 13.1 rows 28/39/51 and the data doc 3.3/12. The doc tests forbid `UNLOGGED` and `job_inputs` in the contract.

Conditions (each is a finding below; none changes the wire):
1. **Per-job sandbox, not a shared long-lived parser (R3-03).** "Shared only with the sandboxed parser worker" lets one compromised parser read every other user's in-flight upload and retain memory across users. The data doc hints at "a read-only bind of exactly one file" but the contract does not require it.
2. **The API-container contradiction (R3-03, N-10).** Contract 5.1 item 9 says the volume "is never mounted into the API container"; the data doc defines the orchestrator as "the API/worker process" with read/write access. Someone has to write the stream to the volume; if that is the Kestrel process, it is mounted into the API container. Decide which process receives the upload and say so.
3. **Output channel (R3-04).** Parser stdout as IPC is captured by the Docker/Kubernetes log driver if the parser runs as a container, which would write the canonical text of every syllabus into host logs. Violates invariant 10.
4. **Memory-backed only (R3-06).** "tmpfs / ephemeral volume (memory-backed or node-local)" is not equivalent: node-local disk is normally part of VM and disk snapshots, which breaks "excluded from backups by construction".
5. **Fair in-flight cap (R3-05).** A global 100 MB cap with no per-user concurrent-upload limit lets one account (or a few) fill it with slow uploads and deny the feature to others. The "one extraction in flight per user" index is taken at job insert, after streaming.

With these five text changes, security sign-off on the design is **conditionally granted for mock-only implementation**. It is not sign-off for real documents.

### (c) New issues from the revision

1. **Nullable snippet after purge.** Schema is coherent (four `allOf` rules force text/context/start/end to null together; fixtures valid and invalid exist; test `Purged_snippets_have_null_text_and_context_together`). But it removes the evidence the batch-approve control depends on: see **R3-01**. Also `precision: exact` stays on a purged snippet (harmless), and no schema rule ties an item's null snippet to the syllabus's `canonicalTextPurged` (cross-resource, server test).
2. **Retention clock.** Contract, schema description, data doc section 8 and `ck_syllabi_retention` agree: writes only, min(180 d, 365 d from creation). Verified, with these notes: data doc also moves the clock on item DELETE (contract list omits it; trivial); the clock for a syllabus with no student writes is `created_at` (needs one sentence); a client that auto-saves can keep the date at the 365-day cap, which is bounded and accepted; retention purge bumps every item's `row_version` so all outstanding ETags and batch `itemEtags` go stale (correct, the representation changed); a restored backup brings back purged text until the job reruns (data doc 12 states it).
3. **Idempotency tombstones and replay after delete.** Logic is sound: path-scoped routes return `404` at step 4; create keys survive as tombstones; late retry returns `404`, never re-creates; fingerprint mismatch is `400`; FK cascade removes the tombstone with the course or account. Issues: N-03, N-04, R3-10. One UX consequence to record: a student who deletes and immediately re-uploads the same file under a reused key sees `404` for 24 hours; clients must generate a fresh key per user action.
4. **Code points versus UTF-16.** Decision is coherent and the astral fixtures pass. The dangerous mismatches are in the data design (N-01, N-02). Schema `maxLength` is loose by statement. Server must count runes (`EnumerateRunes`, verified 200 runes for `Length` 400), never `string.Length`, for title/notes/snippet/context/paste, and `string.Length` for offsets.
5. **FE0E/FE0F exception.** Works as documented for the cases tested (see R2-03), but see **R3-09**: allowing VS15/VS16 after any non-ASCII base is a one-bit-per-character invisible channel, and the pattern allows it after Cyrillic ("я" + U+FE0F). Impact is low because every sink escapes and the AI path strips before the model sees document text.
6. **`row_version` ETag.** Sound: HMAC over type, wire id and version, so tags are opaque, not transferable between resources and survive key-independent restore; not a stored column. See R3-14 for the restore repeat. Compare tags in constant time (implementation note). The syllabus ETag changes on job progress, so conditional GET on the poll target gives little caching; harmless.
