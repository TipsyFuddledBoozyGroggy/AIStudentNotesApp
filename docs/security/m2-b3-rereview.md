### B3-01 Fixed (RAN)
`Clean` now strips control and every Cf character first, then repeats image/link/tag/URL/protocol-relative/bare-domain rules to a fixpoint (cap 16, then a bracket-drop fallback), then neutralises any leftover `<tag-like` with `‹`. Harness results (input => output):
- `<<b>script>alert(1)<<b>/script>` => `alert(1)`; `<<b>img src=x onerror=alert(1)>` => empty; `<<<b>b>script>x` => `x`; `<scr<script>ipt>alert(1)</scr</script>ipt>` => `ipt>alert(1)ipt>` (no tag survives).
- `[[a](b)](//evil.example/x)` => `[a]([link removed]` (no live link; the previous bypass is closed). `[[[[a](b)](c)](d)](//e.com)` => `[a]([link removed]`. `[click](jav<TAB>ascript:alert(1))` => `click)`.
- Unclosed `<img src=x onerror=alert(1)` => `‹img src=x onerror=alert(1)` (inert).
- Zero-width split `ht<U+200B>tps://evil.example/x` => `[link removed]`; bidi override U+202E removed; Unicode tag characters removed; `mailto:`/`tel:` covered by the scheme list; `//host` covered.
I could not make the fixpoint produce a tag, an active markdown link or a scheme URL. The loop terminates (rules only shrink or replace by a fixed string).

### B3-02 Fixed (READ; project concurrency tests RAN and pass)
- Reservation is a `reserved` ledger row plus an atomic conditional global upsert (`TryAddAsync`: `insert ... on conflict ... where spent + excluded <= cap`), inside one transaction under a per-user `pg_advisory_xact_lock(hashtextextended('ai-budget:'+userId,0))`. Per-session and user-day sums include reserved rows, so concurrent callers see each other once the lock is released after commit. Lock order is user lock, then the global row, then insert; settle updates an existing usage row then the global row; there is no cycle, so no deadlock path.
- Fail closed: a reserve failure returns `Unavailable` with no provider call and opens the breaker (`RecordLedgerFault`); a failed settle keeps the reservation counted (over-count, never under-count) and trips the same fault; settle uses its own 10 s timeout and 3 attempts, not the caller's token, so shutdown does not lose a paid call. A write failure no longer clears the shared change tracker (only the one row is detached). The old (b), (c), (d), (e) problems are gone.
- Residual (Info): the estimate is chars/4 plus max output; `Settle` corrects the global counter by `actual - estimate` without a cap check, so a call that costs more than estimated can push a cap over by that delta. Bounded by calls in flight times the underestimate.
- Residual: **N-02**.

### B3-04 Fixed (READ + suite RAN)
Three layers: startup sweep marks all `Pending` as `Unavailable` (`CatchUpRunner.SweepOrphansAsync`); `GET` and `StartAsync` expire a `Pending` row older than `StaleAfter` (120 s); a failed or cancelled job marks its row `Unavailable` using a separate 5 s token. The expiry statement is parameterised, owner-scoped and conditional on `ai_state='Pending'`. A late job finishing after expiry can overwrite `Unavailable` with `Ready` (last writer wins, EF has no concurrency token); that is benign (the result is real and valid). Single-instance caveat: a second instance starting would flip the first one's in-flight `Pending` rows (ADR-020d; Info).

### B3-05 Partially fixed
- (a) Fixed: partial unique index `ux_catch_ups_pending (session_id, window_minutes) where ai_state='Pending'`; a violation is handled by returning the existing row and giving the limiter token back. Verified by reading the catch block and by the in-flight test.
- (c) Fixed: limiter sweep prunes idle sessions once per window (a benign lost-hit race exists between sweep and a concurrent `GetOrAdd`; Info).
- (b) **Not fixed**: still per-session only, no per-user limit; a user with many sessions gets 6/min each. The early "coalesce" return happens before the limiter, so repeat clicks on a pending window are unlimited, but each is only a DB read behind the 120/min global bucket.
- (d) **Not fixed**: `MaxPerSession = 200` is a permanent per-session cap with a bare 429.
- (e) **Not fixed**: a coalesced answer is not bound to the caller's `Idempotency-Key`.
All three leftovers are Low/Info and do not cost money (no paid call is made on those paths). Track as N-10.

### B3-06 Fixed for single instance (READ + suite RAN)
Mechanism: `SessionCutoff` is registered as an `ISessionLifecycleObserver`; `NotifyStateAsync` and `NotifyDeletedAsync` run after `SaveChangesAsync` (`SessionService.cs:199-209`, `253-257`, `286-288`) and swallow observer errors. `AiGateway.RunAsync` takes a lease first, then the Active check (`AiGateway.cs:79`, `114`), then the call under the lease token.
- Ordering argument holds: lease at t0, state read at t1 > t0. If the pause commits before t1, the check sees it (`ISessionDirectory.FindAsync` is `AsNoTracking`, so there is no stale identity-map read inside a scope that makes several gateway calls). If it commits after t1, its notification runs after the commit, therefore after t0, and cancels the lease. Pause then immediate Resume: the in-flight call is cancelled (`SessionClosed`), the segments stay pending, and the next tick after Resume summarises them; a lease taken after Resume works normally. Delete: the session row is gone, `FindAsync` returns null, no call.
- Leak check on cancellation: every path after a successful reservation settles it (cancel => `Settle(...Error)` releases the hold; timeout, client error, generic exception, invalid output likewise). The one gap is N-02.
- Catch-up: a queued job re-checks inside the gateway; `StartAsync` on a Paused session returns `Unavailable` without queuing; a pause after queueing makes the job end `Unavailable` (extractive stays).
- Removed Final summary: the scheduler no longer flushes on Pause or runs a pass on Stop. Consequences (not security defects): a stopped session keeps its last Draft revision and segments after it are never summarised; wire/schema/web still accept `status: "Final"` but nothing produces it. Product/UX should confirm the stopped-session TL;DR is labelled as the last live draft. For the disclosure text: a request already handed to the vendor when the student pauses cannot be recalled; the cut-off cancels the HTTP call but the vendor may still have received it. The window is milliseconds to the call timeout. Record this in the consent/privacy copy owners' list (G1).
- Limits of the evidence: multi-instance is not covered (the lease is in-process; the DB check still prevents calls started after the commit). The suite's cutoff tests passed; I did not run my own pause-during-call stress loop.
- **New: N-01.**

### B3-07 Fixed (READ)
`CleanId` is applied to block `kind` and every line `id`: redacts, then keeps only letters, digits, space, `_`, `-`, `.`, caps at 64. A model-derived topic key can no longer close the `[id @ time]` prefix, the quote of `kind="..."`, or forge a tag. Residual (Info): plain words still pass (a 60-character "ignore previous" id), which is inherent and sits inside the untrusted tag under the standing preamble. Related Info (N-07): `Clean(line.Text)` strips `char.IsControl` but not Cf, so invisible Unicode tag characters in transcript text still reach a vendor prompt; the sanitizer on output strips them, the prompt side does not.

### B3-08 Fixed (READ)
`source` ("mock" or "model") is on summary revisions and on `kind=Ai` catch-ups, in both schemas, parsed by `aiPayloads.ts`, and the UI shows `DemoSummaryTag` when `source === "mock"`. Extractive catch-ups carry no source (they are raw transcript, which is correct). Residual N-08 (Info): `AiSource.Of` returns "model" for any model id not starting with "mock", including an empty string (fail-open label).

## Specific checks requested
- **Own Pause/Stop exemption** (see N-03). Path match is case-sensitive while routing is case-insensitive, so an upper-case route variant is simply not exempt (safe direction). Trailing slash is covered. POST only. Other users' ids are not exempt from anything except the limit, and are answered 404 by the handler. The 36-character class accepts non-GUID strings, but the route constraint `{id:guid}` rejects them cheaply. Auth required: unauthenticated requests keep the IP bucket. CSRF: Origin check is a separate earlier middleware and was not touched. Regression test proves own Pause/Stop work with the write budget exhausted (RAN, passes).
- **Hub negotiate exemption** (`Program.cs:73`). Exempt from the write bucket only; still counted in the 120/min general per-user bucket, Origin-checked, cookie-authenticated. EndsWith("/negotiate") under `/hubs` has no other POST route attached. Acceptable; the new test proves both sides (RAN).
- **Production defaults unchanged**: confirmed by reading `Program.cs:63-67` and `appsettings.json`; only dev compose differs (N-05).
- **Catch-up schema/wire change** (READ + contract tests RAN): `catchup.schema.json` is closed (`additionalProperties:false`) at every level, adds `aiState`, `source`, rich Ai-only fields with caps (3 short, 8 detail, 5 terms, 3 questions, 5 gaps); invalid fixtures for bad state, basis, confidence, unknown field, negative ms, window 3. Server writes the JSON from a typed record; model JSON is validated with closed shapes and sanitised before storage. Web: `parseCatchUp` copies only known fields and regex-checks `catchUpId` before it goes into a URL (also `encodeURIComponent`). Remaining issue is only N-06.
- **Web XSS and storage** (READ of the diff): all server text goes through `PlainText` (text node); no `dangerouslySetInnerHTML`, `innerHTML` or markdown library in non-test files; the only `href`s are static in-app anchors and `Link`. `localStorage` holds only the Quick recap window (2/5/10, validated on read) and the existing four booleans; no transcript, summary, ids or tokens. Reads/writes are try/catch guarded. The Idempotency-Key is `crypto.randomUUID()` in memory only.
